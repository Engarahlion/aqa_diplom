## **План тестирования мобильного приложения "Мобильный хоспис"**.

### **Введение**

Целью создания данного плана является описание процесса тестирования мобильного приложения "Мобильный хоспис".

### **Объект тестирования:** 
Мобильное приложение "Мобильный хоспис".

### **Процесс тестирования:**

1. Исследовательское ручное тестирование методом черного ящика.
2. Составление чек-листа для проверки приложения. 
3. Составление тест-кейсов для проверки приложения.
4. Автоматизация тестов.
5. Создание отчета о тестировании.

### **Предполагается провести:**

**Для отдельных полей:**

- Позитивное тестирование (корректные шаги, валидные данные).
- Негативное тестирование (некорректные шаги, невалидные данные).

**Для всей системы:**

- Исследовательское тестирование;
- Функциональное тестирование;
- UX-тестирование (тестирование юзабилити);
- GUI-тестирование (тестирование пользовательского интерфейса).

**Тестируемый функционал приложения:**

**1. Вкладка "Authorization"**
- Отображение экрана загрузки;
- Отображение всех необходимых элеменов на экране авторизации;
- Авторизация с валидными данными;
- Авторизация с незарегистрированными данными;
- Авторизация с пустым полем логина;
- Авторизация с пустым полем пароля;
- Авторизация с пустыми полями логина и пароля. 

**2. Вкладка "Main":**
- Отображение всех необходимых элеменов на главной странице;
- Обновление главной страницы;
- Сворачивание и разворачивание элемента "News";
- Переход на страницу "ALL NEWS" по ссылке "ALL NEWS".

**3. "Appbar":**
- Переход на страницу "News" из "Main";
- Переход на страницу "News" из "Love is all";
- Переход на страницу "Main" из "News";
- Переход на страницу "Main" из "Love is all";
- Переход на страницу "About" из "Main";
- Переход на страницу "About" из "News";
- Переход на страницу "About" из "Love is all";
- Переход на страницу "Love is all" из "Main";
- Переход на страницу "Love is all" из "News";
- Выход из приложения со страницы "Main";
- Выход из приложения со страницы "News";
- Выход из приложения со страницы "About".

**4. Вкладка "News":**
- Успешное создание новости;
- Отмена создания новости;
- Создание пустой новости;
- Создание новости с несуществующей категорией;
- Создание новости без указания даты;
- Закрытие окна календаря при создании новости;
- Создание новости без указания времени;
- Закрытие окна часов при создании новости.

**5. Вкладка "Control panel":** 
- Автоматическая сортировка новостей от новых к старым;
- Сортировка новостей от старых к новым при применении кнопки сортировки;
- Фильтрация новостей по сегодняшней дате;
- Фильтрация новостей по одной дате "ОТ";
- Фильтрация новостей по одной дате "ДО";
- Фильтрация новости по статусу "ACTIVE";
- Фильтрация новости по статусу "NOT ACTIVE";
- Сброс фильтра по кнопке ОТМЕНА;
- Раскрытие/скрытие описания новости по нажатию на поле новости;
- Открытие страницы редактирования новости;
- Отмена редактирования новости;
- Отмена удаления новости.

**6. Вкладка "Editing News":**
- Редактирование заголовка новости и сохранение изменений;
- Редактирование категории новости и сохранение изменений;
- Редактирование даты публикации новости и сохранение изменений;
- Редактирование времени публикации новости и сохранение изменений;
- Изменение новости на "Неактивна" и сохранение изменений;
- Изменение новости на "Активна" и сохранение изменений;
- Отмена изменения новости;
- Отмена выхода из редактирования новости;
- Удаление новости.

**7. Вкладка "Love is all":**
- Разворачивание/сворачивание любой цитаты;
- Отображение всех 8 цитат.

**8. Вкладка "About":**
- Просмотр ссылки "Политика конфиденциальности";
- Cсылка "Privacy Policy:" ведет на соответвствующий документ/страницу;
- Просмотр ссылки "Пользовательское соглашение";
- Cсылка "Terms of use:" ведет на соответвствующий документ/страницу;
- Отображение текущей версии.

**Перечень используемых инструментов для автоматизации тестирования:**

**1.** Android Studio -  интегрированная среда разработки (IDE) для работы с платформой Android;

**2.** Java 11.0.28 - строго типизированный объектно-ориентированный язык программирования общего назначения;

**3.** Expresso - нативный фреймворк для тестирования.

**4.** JUnit 4.+ - тестовый фреймворк. Библиотека для модульного тестирования программного обеспечения на языке Java.

**5.** Gradle - система автоматической сборки проекта.

**6.**  Allure - популярный инструмент построения отчётов, упрощающий их анализ.

**7.**  [Faker](https://fakerjs.dev/) - генерирует поддельные данные для тестирования или заполнения базы данных для разработки. [Дополнительно](https://github.com/blocoio/faker)

**Перечень и описание возможных рисков при автоматизации тестирования:**

1. Несоответствие версии Java с Gradle;
2. Возможность появления сложности в поиске id элементов;
3. Возможность выявления дефектов в приложении.

**План сдачи работ**

1. Составление плана тестирования, чек-листа, тест-кейсов - 2 дня;
2. Настройка окружения, написание и отладка автотестов - 10 дней;
3. Подготовке отчётных документов по итогам автоматизированного тестирования 1 день;
4. Подготовка отчётных документов по итогам тестирования 1 день.
